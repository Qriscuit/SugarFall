# Monetization account setup

10 November 2026. The owner’s AdMob account contains the unpublished Sugarfall Android app. The **Result bonus** rewarded unit and **Campaign results** interstitial unit were created and verified in the dashboard. AdMob shows **Requires review** and **Limited ad serving** with no store link. Privacy & messaging offers creation of new European and US state messages. No purchase verifier is deployed. Active Play products, native phone playback and Play submission remain unverified.

[Billing config](../../data/monetization_config.json) has empty `billing.verification_url`, `billing.firebase_web_api_key` and `billing.firebase_project_id`. [Production ads](../../data/production_ads.json) use Sugarfall’s app and ad units. [Preview ads](../../data/preview_ads.json) use Google’s demo inventory in the separate preview package.

1. **Choose and authorize Firebase setup.** Cloud Functions deployment requires the **Blaze pay-as-you-go plan with a linked Cloud Billing account**. The owner must choose and approve the project, plan/billing account, Functions region and database location before creation, upgrade or deployment. Prepared source and the AAB do not authorize spending. Then register Android package `com.sungati.sugarfall`, enable Anonymous Authentication and record the project ID/Web API key. Anonymous identity authenticates requests; it is not permanent purchase ownership. [Functions deployment prerequisites](https://firebase.google.com/docs/functions/get-started), [Firebase anonymous Auth](https://firebase.google.com/docs/auth/android/anonymous-auth).

2. **Deploy and verify the purchase service.** Follow the [backend handoff](../../../server/commerce/README.md): inspect the native Firestore database/edition, set the exact database/region/runtime identity, review deny-client rules and grant minimum IAM. Enable the Android Publisher API and give the attached service account app-level Play purchase verification/acknowledgement permissions. Use ADC; put no service-account key in the game. Verify the returned HTTPS function URL, then fill the three `billing` config fields from the same project. For license testing, explicitly enable `COMMERCE_ALLOW_TEST_PURCHASES=true` on the test deployment; production defaults to false. [Google API setup](https://developers.google.com/android-publisher/getting_started).

3. **Activate the permanent Play products.** Configure the exact one-time, non-consumable product IDs and purchase options below. Confirm approved pricing and available regions. The existing design price for each area ability is US$2.99. Set the ad-removal price in Play. The verifier matches each product to its purchase option and acknowledges after durable delivery.

   | Product | Product ID | Purchase option |
   |---|---|---|
   | Bakery ability | `sugarfall_bakery_ability` | `early-unlock` |
   | Gelato Garden ability | `sugarfall_gelato_ability` | `early-unlock` |
   | Crystal Candyworks ability | `sugarfall_crystal_ability` | `early-unlock` |
   | Remove automatic ads | `remove_ads` | `remove-ads` |

4. **Finish consent and ad acceptance.** Confirm the launch audience, countries and public privacy policy URL. Publish the applicable Privacy & messaging forms for Sugarfall. Declare **Contains ads** in Play and complete the audience and SDK data disclosures. Register the acceptance phone as an AdMob test device before exercising owner inventory. Verify the consent prompt and Settings privacy options where required, the optional result bonus after a completed ad, cancellation without a bonus, and the automatic ad at an eligible result. Shared preview testing uses Google demo units. [UMP setup](https://developers.google.com/admob/android/next-gen/privacy), [Next-Gen test ads](https://developers.google.com/admob/android/next-gen/test-ads), [Play App content](https://support.google.com/googleplay/android-developer/answer/9859455), [SDK data disclosure](https://developers.google.com/admob/android/privacy/play-data-disclosure).

5. **Upload the signed AAB to Internal testing.** Use the public `com.sungati.sugarfall` build, existing upload/signing identity and an unused higher version code. Review its exact package, signature and payload first. In Play Console, create an Internal testing release, upload the AAB, resolve Console requirements, select testers and release to that track. Testers opt in and install through Play. Once the public listing is available, link it in AdMob and verify `app-ads.txt` on the developer website so Google can complete the app readiness review. [Testing tracks](https://support.google.com/googleplay/android-developer/answer/9845334), [AdMob app readiness](https://support.google.com/admob/answer/10564477), [App verification](https://support.google.com/admob/answer/14538460).

6. **Add license testers separately.** Add the purchasing Google accounts under Play Console License testing as well as the internal track. **Internal testing does not automatically make purchases free.** Confirm the purchase dialog uses the licensed account and a Google test payment method; non-test payment methods can charge money. Test approval, decline, pending, duplicate callbacks, acknowledgement retry, fresh-install restore, refund/revocation and offline expiry. Purchases must appear only after verified server success; demo ads require actual SDK callbacks after consent readiness. Record device, installed version and outcomes. [Play Billing testing](https://developer.android.com/google/play/billing/test).

Production acceptance still requires AdMob readiness approval, the store and consent declarations, and recorded Android ad playback. Paid unlocks and ad removal require the production verifier and purchase/restore acceptance. For ad removal, use **Settings → Purchases** on the Play-installed build. Confirm an unowned account can see an eligible automatic break, an approved purchase suppresses future automatic breaks, and an optional rewarded ad can still grant its bonus. Check relaunch, reinstall with the same Play account, manual restore, pending/cancelled payments and refund/revocation.
