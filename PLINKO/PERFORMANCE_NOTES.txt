PLAYER EVIDENCE
The player identified a Pixel 6 and reported more lag while many pegs were present, improving as pegs disappeared. That correlation did not establish whether collision, procedural rendering, audio, GPU work or another component caused the problem. This patch addresses measured CPU work while preserving gameplay.

AUDIO AND CHECKPOINTS
Previously each allowed sound synthesized its PCM synchronously. Cloud median generation for45ms combo tones was~0.23ms and130ms pulse~0.69ms; cached playback lookup was~0.004ms in the initial control. The shipped bank contains31streams and53,346PCM bytes plus resource overhead. Fixed tones are byte-identical, while random hit pitches round to nearest5Hz. Sound throttle and gameplay RNG calls stay unchanged.
Checkpoint saves measured~0.25ms fresh,0.66ms representative mid-run and1.88ms at artificial80ball/34peg stress. The save implementation was intentionally not rewritten: preserving atomic interruption safety outweighed the small fingerprint-cache gain. On-device storage latency remains unknown.

RENDERING CHANGES
Original vector artwork caches the paper dots, tray dots and eight normal/flash peg sprites at import. Dynamic HP rings remain live. Rounded panels reuse style resources. Static screens no longer rebuild their draw commands every frame. The display is capped at60FPS, physics remains60Hz, and optional local diagnostics expose FPS and CPU measurements without telemetry.

VALIDATION AND NEXT CHECK
The full prior behavior/resume/profile suites pass. Actual cloud Linux GUI shows correct textured pegs, readable HP, working gameplay, result restore, local diagnostic display and map input. Physical Pixel6 testing is still needed. Install as an update without deleting the save, enable Setup→Performance Display, and compare a previously laggy board at similar peg/ball counts. Report FPS near start/end, sound setting, heat/battery-saver state and any visible stutter. GPU-specific profiling and release-grade device coverage remain open.

ENGINEERING CONSTRAINT
The broadphase assumes stationary pegs and the current maximum9px ball radius. Future moving pegs or larger balls must update its cache invalidation/bounds. Current build_wave and snapshot array replacement are covered. No third-party analytics or profiling SDK was added.
