# Sugarfall screenshot capture — 5 November 2026

Run `run_capture.py` using the workspace Python runtime. It copies the current `PLINKO/scripts` and `PLINKO/data` into a separate project, uses isolated APPDATA/LOCALAPPDATA/TEMP/TMP folders and a unique user directory, then exports a nondebug Windows build with the `sugarfall_public` feature. It leaves production files and player profiles unchanged. A fresh run directory is required; change `WORK` to a new sibling for a rerun.

The fixture inherits the real game renderer and physics. Only the fixture's setup, timing, input and save/load overrides differ. Automatic processing is disabled so deterministic 120 Hz simulation can be advanced between screenshots. Game draw functions are not replaced. Campaign trays, levels, equipment and wallets are staged in memory. Normal ability and map purchase APIs are used. This is a visual record of attainable states, not evidence of how long a player takes to earn them.

The first three images show the three areas during actual simulation. The fourth shows Gelato's current upgrade map after 22 successful ordinary-node purchases. The fifth records the first natural Jam Burst contact after its earned purchase. The sixth records Dual Shot after an earned purchase and Power reset. The seventh taps a live Crystal Prism through its production collection API, checks that all live balls were duplicated, advances 0.2 seconds, then captures the diverging original and duplicate balls.

All final images are directly saved from a 1080 × 1920 Godot viewport as RGB8 PNGs, without generated content, compositing, captions, frames or developer UI. Pixel-format validation and a contact sheet are produced by `verify_captures.py`. When `outputs/storefront-20261105/qa/independent-screenshots-review.json` exists, the validator checks its seven PNG hashes and exact capture/source-evidence hashes before marking visual checks passed. `source-evidence.json` records the actual working-tree resource hashes, fixture hash and executable hash. The current working tree includes intentional uncommitted game/interface work; the Git revision alone does not identify those exact resources, so use the resource hashes.

These are desktop-rendered store-review images. They are not physical Android screenshots or phone acceptance. Compare against the exact signed Android release before store submission. This task creates no APK and uploads no files to Google Play or Drive.
