# Android AdMob provider

10 November 2026. Public Android uses Sugarfall’s rewarded and interstitial units. The shared preview uses Google demo units. Physical playback and AdMob approval remain open. [Account setup](ACCOUNT_SETUP.md).

`res://scripts/admob_provider.gd` is a Node. Add it to the game tree, connect its signals, and call `initialize(config)` with either the complete monetization configuration or its `ads` dictionary. `res://scripts/admob_native_adapter.gd` binds the installed Poing native singletons. Production initialization requires Android and the real native singleton set before the bridge is loaded; the addon's editor mocks cannot supply production rewards.

| API | Contract |
| --- | --- |
| `initialize(config) -> bool` | Starts native UMP consent refresh. True means the native flow started, not that consent, SDK initialization or inventory is ready. |
| `is_initialized() -> bool` | SDK initialization completed successfully. This alone does not mean an ad is loaded. |
| `is_ready(kind) -> bool` | Kind is `rewarded` or `interstitial`; requires consent, initialized SDK, matching native-loaded inventory, foreground state and no competing fullscreen request/form. |
| `show(kind, request_id, context="") -> bool` | True accepts a caller-keyed asynchronous request; false accepts nothing and emits no outcome. The caller binds context to the run and persists grants idempotently. |
| `reward_earned(request_id, reward)` | Signal emitted once immediately on the native reward callback. Persist the request/run grant now so interruption before dismissal cannot lose it. |
| `request_finished(request_id, result)` | Signal after native dismissal, show failure or cancellation. Dictionary fields: `status`, `outcome`, `kind`, `context`, `granted`, `reward`, `error`. Outcomes are `completed`, `cancelled` or `failed`. A rewarded request is granted only after a native earned callback; interstitial completion never grants a reward. The same request ID must be deduplicated with the earlier earned signal. |
| `availability_changed`, `consent_changed` | Signals tell the UI to re-read status. |
| `status() -> Dictionary` | Separate `initialized`, `initializing`, `consent_ready`, `consent_loading`, `consent_error`, `privacy_options_required`, `privacy_open`, per-format readiness/loading/errors, pending state and test mode. |
| `show_privacy_options() -> bool` | Opens the real UMP privacy options form when required; blocks competing fullscreen ads. |
| `refresh_consent() -> bool` | Starts another native refresh only when no other consent form/request is in flight. It invalidates inventory first. |
| `set_suspended(bool)` | Blocks new ad presentation and pauses retry/grace clocks while backgrounded. Native earned/dismissal callbacks remain accepted for the current request. |
| `shutdown()` | Disposes native handles, ends pending UI, retains a real reward already earned, and rejects later callbacks. |

Messages and availability are driven by actual native callbacks. There is no fake success path. No fill and native errors remain unavailable and use a 5–60-second retry backoff; loads/initialization time out after 45 foreground seconds. Cached ads refresh conservatively after 45 minutes. Reward-first and dismissal-first orderings are both handled. A dismissed rewarded ad remains alive for a two-second foreground grace so delayed earned events can arrive; if none arrives it cancels. Next-Gen 1.6.0 includes Google's native reward-order fix. A later show error or shutdown cannot revoke a native reward already earned.

`native_ad_service.gd` implements the game's durable request ledger and production cadence. `main.setup_native_ads(config, restored_state)` imports the independent `native_ads` profile namespace before starting consent. Native playback requires four distinct completed campaign attempts and 120 seconds of active campaign play for an automatic interstitial; a loaded optional rewarded ad can be offered at an unclaimed result. Ads never start inside a run, Trial, onboarding, paused transition or background state. The developer simulator has its own policy and is disabled when the native service is available.

The controller saves the consumed cadence and unique request serial before requesting SDK playback. It binds the request to the current profile, area and run. Only the native `reward_earned` event creates a receipt, which is saved immediately before waiting for dismissal. The result receives one 50% base-earnings bonus from that durable receipt. Terminal outcome flags, dismissal, no fill, cancellation and failure cannot create receipts. Save failure keeps the earned receipt in memory, retries storage in the foreground and holds Collect until the bonus is durable. Duplicate and unrelated callbacks are ignored. The ledger retains the latest 256 reward receipts; in-flight ads are excluded from saves, so restarting never invents completion. A saved earned receipt restores with its pending result and collects once.

`native_ad` keeps the existing result frozen and blocks game input during actual SDK presentation. The result action reads "Watch ad +N", exposes loading/no-fill/privacy errors inline and returns to Collect after dismissal. Consent readiness remains separate from inventory readiness. `NativeAdService.status()` and `show_privacy_options()` expose the real UMP privacy-options requirement and form to Settings. Provider memory retains the most recent 256 terminal IDs as an additional local guard.

The public configuration is `res://data/production_ads.json`. The preview configuration is `res://data/preview_ads.json`. Each is a flat JSON object with `enabled`, `app_id`, `rewarded_unit_id`, `interstitial_unit_id`, `use_test_ads`, and optional ad policy settings. The `consent` object holds UMP settings. Test-device overrides and debug geography belong to preview only. Consent comes from native UMP. UNKNOWN and REQUIRED block loads. OBTAINED and NOT_REQUIRED allow SDK initialization. Privacy changes invalidate inventory.

The public feature selects the production profile at runtime and in the Android exporter. Both use the same app ID source, and the verifier compares the packaged config to the manifest. Production requires explicit `use_test_ads:false` and valid owner IDs. The export excludes the other profile’s JSON. The preview profile selects the Google SDK demo flow. Enable `res://addons/admob/plugin.cfg` and Android Gradle export. The native libraries require compile SDK 35 or later and app min SDK 24.

## Pinned sources and local changes

- [Poing 5.1.0 release](https://github.com/poingstudios/godot-admob-plugin/releases/tag/v5.1.0), published 2026-09-13. Wrapper ZIP SHA256: `8c53ff52719edf6a81cc7d32a9cdaad2d9e11693c85faca25008a1c19355726f`. Android 4.6.3 template ZIP SHA256: `f7fdf644d50c0e231d8f02ae044057e489d0bcafcf50e908a4858477e7ee05ee`. Both were checked against the release metadata before extraction. Full [MIT license](../../addons/admob/LICENSE) retained.
- Android `ads` module only; no mediation native modules installed. Unused C# and skill packages were omitted from this GDScript project. Wrapper/editor/GDScript API assets are retained.
- `addons/admob/android/bin/ads/poing_godot_admob_ads.gd`: explicit Google dependency changed from `ads-mobile-sdk:1.4.0` to **`com.google.android.libraries.ads.mobile.sdk:ads-mobile-sdk:1.6.0`**. Native release AAR bytes are unchanged.
- `addons/admob/admob.gd`: automatic missing-binary download call removed during editor startup/export. Verified native binaries are vendored; builds do not silently download iOS libraries or overwrite pinned dependencies. The explicit AdMob Manager remains upstream behavior.
- `addons/admob/android/.gitignore`: upstream `bin/` ignore removed so the verified native binaries are version-controlled. This changes VCS tracking only; native bytes and runtime behavior are unchanged.
- [Google Next-Gen 1.6 release notes](https://developers.google.com/admob/android/next-gen/rel-notes) identify the 2026-10-22 reward-after-dismiss and R8/WorkManager fixes. [Official setup](https://developers.google.com/admob/android/next-gen/quick-start) provides the artifact and minimum API requirements. Google's 1.6 POM resolves UMP 4.0.0 and hsdp 2.2.0. Official AAR and POM downloads were checked against Google's published SHA1 values; SHA256 values are retained in verification.

## Verification

The focused fake-native adapter suite passes **55 checks** with zero failures, covering consent/readiness, demo-ID isolation, reward/cancel/error ordering, exactly-once caller IDs, retry/timeouts, background behavior, immediate earned persistence signal and shutdown. Fake events are confined to `tests/admob_provider_qa.gd`; they do not establish that native ads were displayed.

`tests/native_ad_integration_qa.gd` additionally passes **40 checks** for production cadence, ready-versus-accepted requests, pre-playback persistence failure, native reward receipts, duplicate/unrelated/cancelled callbacks, foreground save recovery, frozen main input, actual payout/Collect and real on-disk profile restart. It requires `--native-ad-qa-isolated` and an isolated profile. `tests/native_ad_preview.gd` renders **12 captures** of the actual ready/loading/no-fill/privacy-error/earned/confirmation UI at 450×800 and 720×1280 with a test-only provider; all layout checks pass. Current integration evidence is in `verification/native-ad-integration-20261105/`; these fixtures do not establish Android SDK playback or phone acceptance.

`verification/admob-provider-20261105/native-api-compatibility.json` confirms all **80 referenced SDK classes and 210 SDK field/method signatures** from the exact vendored release AARs resolve against Google's actual 1.6.0 Ads and 4.0.0 UMP class files plus installed Android 36 framework declarations. The AAR metadata declares minCompileSdk 35 and minAndroidGradlePluginVersion 1.0.0. This static linkage audit does not establish a complete Android dependency graph, device execution, consent message configuration or successful native ad delivery. Those remain build/device gates.

Raw logs, downloaded public packages, exact source bindings and the checker live under `verification/admob-provider-20261105/`. Earlier attempts remain history. No live ad request, account change, phone acceptance or production serving is claimed by this source verification.
